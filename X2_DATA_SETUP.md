Verified 17 November 2026 against primary vendor documentation. No provider key or commercial financial-data licence was present in the starting runtime. No subscription, demo token, purchase, broker connection or additional paid database was used.

## Owner setup

1. Root integrates `X2_OWNER_SUBJECT` as a server-only runtime binding to the verified owner's native stable subject. All provider settings fail closed when it is missing. Per-Soul `ownership` is not an administration role and is never used to infer owner privilege. Ordinary users receive only `{isOwner:false}` from the capability probe.
2. In this existing Site's runtime environment settings, enter the applicable server-only secret variable above. Data Connections contains no key/password field, cannot install a runtime secret, and never returns secret values. Secrets must remain absent from the repository, D1 metadata, browser/localStorage and logs. EODHD requires its documented query-token auth on the fixed server-side vendor request; raw URLs/errors are never returned or logged by this implementation.
3. Open owner Data Connections. Add exact canonical-to-vendor instrument mappings, IANA timezone, venue MIC, currency, unit and type. MCX futures require actual expiry, lot size and tick size; no made-up expiry or continuous-contract execution identity is accepted. The initial mapping template is deliberately invalid until a verified vendor symbol replaces the prompt text.
4. Record the actual contract reference, expiry and separate raw display, non-display analysis, derived display, historical-storage, cache and redistribution rights. Select only entitled datasets, a local daily call cap and routing priority. Rights are **owner-attested**, not magically verified by an HTTP 200; the provider endpoints do not validate legal redistribution terms. Never check a box without actual entitlement evidence.
5. Save metadata, then Test connection. The test probes one bounded mapped instrument per market, validates the actual schema/date/OHLC, records accepted/rejected identities, source time, elapsed latency and recorded local-call allowance. Status can be not configured, entitlement not verified, connected, partial, auth failed, rate limited, provider down or disabled. Source test does not turn a current historical endpoint into verified LIVE.
6. Confirmed saves/tests dispatch `x2-data-updated`; the shell refreshes its shared overview and registry. Asset views and scans reread config, supported secrets and rights. No frontend source change is needed for mapping/rights rotation. **Sites runtime secret insertion may require its supported publish/restart process**; this implementation does not claim secrets change inside an already running deployment without that platform step.

## Shared activation contract

`GET /api/x2/data?view=instruments` returns `{instruments}` with identity-only seeds plus permitted owner mappings. `GET /api/x2/data?view=overview&ids=NSE:...` returns the existing MarketSnapshot fields with merged `quotes` and separate `marketQuotes`; at most eight mapped daily histories are requested, concurrently, within local provider quotas. No key means no connected-market number. An unmapped identity remains unavailable. Each accepted close carries source date, retrieval time, currency/unit, daily-OHLC cadence and PUBLISHED_EOD/STALE state. Source failure cannot create a live badge or an alternate instrument's price.

`assetResearch` and `researchUniverse` consume the same service. Scan datasets additionally require explicit non-display **and storage** rights because executed scan snapshots persist. Future queries recheck current permissions; old cache keys are invalid after config changes or secret rotation, expiry is bounded by contract expiry, and in-flight results are rechecked against active configuration before publication. Histories from different providers are never spliced.

`researchUniverse` supports provider `ECB` (default), `CONNECTED_MARKETS` (excludes ECB), `EODHD` or `TRUEDATA`, optional exact instrument IDs and daily/weekly/monthly interval. It returns typed ScanDataset arrays, excluded reasons, source/adjustment lineage, rights and as-of time. Both `pointInTime` and `adjusted` remain false for these adapters: vendor adjusted-close history can be revised retrospectively, raw OHLC is not adjusted total return, and historical release instants/vintages are absent. The probability/backtest engine must continue to suppress a live validated forward score.

## Chart terminal and private layouts

`AssetTerminal({id,onClose?,onAnalyze?:(formula?,instrumentId?)=>void,notify?})` is a default export without its own modal. It supports source-aware line/candlestick/OHLC modes, daily/weekly/monthly aggregation, pan/zoom, price crosshair/OHLC readout, actual source-volume panel, indicator overlays and oscillator panels, normalized same-date peer price comparison and accessible source table and named private presets. Reference-only feeds cannot select fake candles. Implemented numerical functions: SMA, seeded EMA, Wilder RSI, MACD, population-standard-deviation Bollinger bands, Wilder ATR, drawdown, session-VWAP function (not activated on daily data), relative strength and same-period ratio/comparability helpers.

Price/date anchored horizontal levels, trendlines, rays and Fibonacci tools are editable/undoable/removable. Save uses owner-scoped optimistic versions, stable retry keys, a synchronous pending guard and a 100-layout cap enforced in the write statement. Fundamentals/statements/events honor applicability and missing data; a company statement is not attributed to a commodity/index. Current provider Greeks/options chain, intraday VWAP, depth-based volume profile, licensed universe-wide sector heatmaps and calibrated historical probability remain **unconnected/not implemented as live capabilities**. Formula Lab supplies theoretical derivatives tools separately. No disabled icon forest or fabricated data fills those gaps.

Root imports `components/x2/data.css` and integrates the two default components. Drizzle exports required: `db/x2-data.ts` defines three additive tables (`x2_providers`, `x2_provider_audit`, `x2_chart_layouts`); the sole integrator generates/applies the combined migration. No existing table is replaced.

## Independent-review corrections

Three release-blocking boundary findings were corrected and regression-tested. Display-only source access no longer executes or shows client indicators, normalized peer comparisons, technical presets or calculated drawing/aggregation tools. `capabilities.analysis` and the separate owner-attested `rights.derivedDisplay` grant are both required. Existing configs without that explicit derived grant default to denial; raw licensed daily displays remain available. Overview percentage changes are also suppressed without both grants.

Financial statement booleans, blank strings, nulls and malformed/nonfuture filing dates are not coerced to zero or a known publication instant. Only valid actual zero remains zero; missing currency/basis/filing lineage stays explicitly unknown, with quality notes. Fiscal dictionary dates are validated as real nonfuture dates as well.

Non-display-only scanning now uses private purpose-specific ingestion pinned to the analysis+storage eligible provider, rather than reselecting a higher-priority display provider. Public asset/overview readers cannot request this ingestion purpose; display/analysis caches are segregated. Each scan lineage entry carries `displayAllowed`, `derivedDisplayAllowed`, `rightsExpiresAt` and `configVersion`. `currentDisplayRights(instrumentId,provider)` supports read-time projection/revocation; legal rights are independent of a still-valid provider key. Integrator must redact raw stored snapshots and numeric reason strings at history/detail/export boundaries when rights do not permit display; this is a separate downstream API responsibility.

Actual `evaluateScan` integration now verifies the strict scanner accepts source DATE precision markers (`YYYY-MM-DDT00:00:00.000Z`) while the separate known-at instant remains the conservative retrieval timestamp. This marker is not claimed as the original publication time. Both ECB and connected-provider service datasets pass a real deterministic scan fixture; point-in-time backtests remain blocked.

New tests prove no access to source values inside a denied client analytics helper, malformed/future filing dates, two competing providers with distinct raw-display versus non-display rights, no analysis-cache escape through asset/overview GET, and the actual service-to-engine timestamp contract. These are isolated fixtures, not live provider activation.


Browser-derived scope/interval regressions: an explicitly empty instrumentIds array now means the full eligible universe, matching an omitted scope; a nonempty array still narrows to exact source IDs. Actual-service tests cover ECB and connected-market default/exact/missing scopes. Weekly/monthly ECB scans now group actual references with aggregateReferences, preserve the final actual source date and conservative knownAt, and record interval plus a latest-calendar-group-may-be-partial policy in lineage. Aggregation does not invent OHLC, publication instants or completed-period status.
