# X2 research, probability and Graveyard contract

Implemented 17 November 2026 on the existing Workers/D1 stack. No new research table, service, subscription or runtime dependency. Existing X1 scan payloads/digests are never rewritten. New executions require trimmed 3–100-codepoint names, 10–2,000-codepoint descriptions, a canonical safe rule, universe/timeframe, registered outcome/horizon, source scope and partial-data policy.

## Working workflow

`components/x1/strategy.tsx` now reexports the modular `components/x2/research-workspace.tsx`. The original Formula Lab is preserved in `components/x2/formula-lab.tsx`. A recursive Simple editor supports ALL/ANY/NOT, drag reorder and equivalent up/down/delete controls; Advanced uses the same parser. Switching back preserves unsupported expressions rather than flattening them. Explicit source preflight precedes Run. No instruments/all UNKNOWN blocks execution; partial UNKNOWN requires affirmative policy selection. Root-provided `initialInstrument` constrains both the source universe and exact IDs, so an NSE asset cannot silently scan ECB FX.

Versioned drafts use existing owner-scoped `x1_records` with 50-version and 100-active-record bounds. Create retries are keyed; update CAS rejects concurrent overwrites. Save/run status uses synchronous mutation locks and stable retry IDs. Dirty state sends only a boolean `x2-research-dirty` event to the shell and also registers beforeunload. The caller's root navigation owns the confirmation. Successful save/run/share clears the flag. Existing names/descriptions can be reused for a new immutable execution; original runs remain intact. Scan reviews are retry-safe when a stable request ID is supplied.

The UI provides named history search, separate Graveyard reviews/restoration, filtered PASS/FAIL/UNKNOWN explanations, authorized asset crosslinks, exact source digests, drafts/version history, side-by-side rule/outcome/coverage comparison, personal evidence privacy, similar permitted runs, registered outcomes, calibration diagnostics when present, and source-gated replay/backtest views. Radar opens editable technical/volume/event rules with prerequisites; unsupported fields are not replaced with fake values.

## Outcomes and reproducible research

`lib/x2/research.ts` labels positive adjusted horizon return above the registered threshold, or target-before-stop. Costs are explicit round-trip basis-point assumptions. Opening gaps resolve the first observable barrier; later OHLC bars touching both barriers remain AMBIGUOUS. Unmatured horizons are right-censored, not losses. A missing/late earlier observation cannot be skipped to manufacture maturity. Complete future history is still filtered by the query's known-at cutoff.

Pure historical replay evaluates each rule at its original signal cutoff and requires licensed point-in-time adjusted history plus storage rights. Current ECB history has retrieval-time known-at, and current provider adapters do not certify historical vintage availability, so production replay is **DATA UNAVAILABLE**. No historical outcomes are drawn for appearance.

`lib/x2/backtest.ts` implements a bounded single-instrument unlevered, long-only next-observation-open simulation, non-overlapping positions, registered horizon/barrier exits, assumed costs/slippage, model equity, close-based drawdown, turnover, censoring and compatible verified benchmark comparison when supplied. Ambiguous bars use a clearly labelled conservative stop-first scenario in the model curve, while remaining excluded from binary probability evidence. Missing OHLC/PIT/adjustment/retention, over-1,000-observation windows and insolvent cost/gap assumptions suppress output. These are hypothetical models, not execution/fill evidence or promises. Daily close drawdown does not claim unknown intrabar paths; source universe/corporate-action/survivorship limits remain material.

## Evidence estimator and release gate

History contains all executions. Graveyard contains explicit negative/retired reviews and is a selected sample; it never supplies a success denominator alone. Case filtering uses exact canonical rule/outcome/horizon/cohort, source/PIT/retention flags and matured known-at cutoff. Same-cluster overlapping windows and duplicate shared events are removed before scoring. Personal opt-out is checked before counts or links. Pure aggregate fixtures require explicit, nonwithdrawn consent and return no other user's case IDs, titles or strategy links. Production cross-user aggregation remains disabled; group membership is not training consent.

The transparent estimator is a Beta(1,1)-shrunk constant conditional-cohort frequency fitted only on the first chronological 60%, with 20% validation and 20% holdout; overlapping label windows are purged at split boundaries. Its held-out Brier, calibration-in-the-large, five-bin ECE/reliability table and verified unconditional/cohort baseline are evaluated. Default engineering gates require at least 100 resolved non-overlapping observations, 50 signal dates, 50 training / 20 validation / 30 holdout examples, both outcome classes in each partition, a Wilson interval width <=0.30, validation/holdout ECE <=0.12, holdout calibration bias <=0.12 and Brier no worse than the verified baseline by more than 0.005. These configurable thresholds are conservative software gates, not proof of market independence, stationarity or statistical adequacy.

The displayed interval, if released, is a Wilson score interval on the training binomial cohort; descriptive all-case counts/interval remain separately labelled. The [NIST confidence-interval reference](https://itl.nist.gov/div898/handbook/prc/section2/prc241.htm), checked 17 November 2026, supports the Wilson implementation. Correlated market cases still require a defensible cluster definition and independent model review before production validation. Any failed source, consent, baseline, calibration or drift gate suppresses the numerical forward estimate. No arbitrary AI confidence meter or percentage is substituted.

`researchEvidence(subject,scanId)` retrieves only the current owner's latest 100 runs not later than the selected execution's timestamp, and at most 20,000 eligible cases. Similar case links are owner-only. Current providers supply neither certified historical cohorts nor a contemporaneous unconditional baseline, so the production probability state is **INSUFFICIENT EVIDENCE**, with no numerical forward probability. This is the actual product state, not a mock estimate hidden behind an absent key.

## Read-time display entitlement correction

`lib/x2/scan-projection.ts` is the single serializer for scan history, detail, full workspace export, preflight results and the immediate run response. Executions preserve creation-time `sourceLineage` flags, while every read intersects them with `currentDisplayRights(instrumentId,provider)` and licence expiry. No key is serialized. Legacy actual ECB provenance remains readable; unknown provenance fails closed. A key expiring does not itself revoke a still-active stored-source licence.

Non-display inputs remain only in the permitted immutable server snapshot/hash. Raw observations and price/volume reason strings never appear in a restricted response. Explicit derived-display grants may expose whitelisted derived statuses, return summaries and normalized curves, with no entry/fill price or unrecognized future raw fields. Without that grant the response uses WITHHELD, null result counts, and no replay/backtest values. Current rights revocation applies to reads/exports without rewriting old evidence. Payloads carry redaction metadata; `digestScope` is FULL_STORED_SNAPSHOT and `digestVerifiableFromResponse` is false for metadata/redacted projections. The UI explains this distinction and labels withheld values.

The evidence service reads its internal owner-scoped database snapshot, rather than using the redacted API projection as calculation input. Its returned score/case outputs separately obey derived-display scope. Source-sensitive input diagnostics are also removed from preflight responses, closing the path before a scan is saved.

Latest targeted verification: **51 passed, zero failed** (30 route/SQLite workspace tests plus 21 mathematical/backtest tests). Added regressions prove non-display raw data is absent from preflight, immediate run output, history, full detail and full export while the stored snapshot/hash remain intact; explicit derived-only summaries omit raw fields; current grant revocation suppresses derived results; and legacy ECB digests/payloads remain unchanged.
